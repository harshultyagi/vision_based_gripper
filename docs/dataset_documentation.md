# Dataset documentation — Cornell Grasping Dataset (local copy)

All numbers on this page come from `experiments/results/dataset_stats.json`,
`dataset_exclusions.json` and `crop_analysis.json`, produced by `scripts/inspect_dataset.py` and
`scripts/make_splits.py`.

## Setting up your own copy

1. Obtain the Cornell Grasping Dataset (it is not redistributed here). The loader expects the
   folder layout below, including the `pcdXXXXd.tiff` depth images. These are not part of the
   original Cornell release: they are the files generated by the GG-CNN repository's
   `generate_cornell_depth.py` script, and the local copy used here already contains them.
2. Copy `configs/local.example.yaml` to `configs/local.yaml` and set `dataset_root`, **or** set
   the environment variable `GRASP_DATASET_ROOT`. Nothing else in the code refers to the location.
3. Run `python scripts/inspect_dataset.py`: it fails loudly if the folder is wrong.

## Local structure (verified)

```
<dataset_root>/
  01/ ... 08/   100 scenes each      09/ 50 scenes     10/ 35 scenes      -> 885 scenes
  backgrounds/  11 background-only RGB images (pcdbXXXXr.png), no annotations, unused
  per scene XXXX (0100 … 1034):
    pcdXXXX.txt      point cloud, PCD v0.7 ASCII, fields x y z rgb index (unused)
    pcdXXXXr.png     RGB, 640 x 480 x 3, uint8
    pcdXXXXd.tiff    depth, 640 x 480, float32, metres (median ≈ 1.1–1.2 m)
    pcdXXXXcpos.txt  positive (graspable) rectangles
    pcdXXXXcneg.txt  negative (non-graspable) rectangles
```

### Annotation format

Each rectangle is **four consecutive lines** `x y` (column, row, floating-point pixels), e.g.
the first rectangle of `pcd0100cpos.txt`:

```
253 319.7
309 324
307 350
251 345.7
```

Edge `p0→p1` (here ≈ 56 px) lies along the **gripper closing direction**: its length is the
opening width. Edge `p1→p2` (≈ 26 px) is a jaw plate. This was confirmed visually: the rectangle
spans the remote control in scene 0100 across its short side.

## Modalities used

* **RGB-D** (4 channels: depth, R, G, B) for the main experiments (GR-ConvNet's best published
  configuration); **RGB** only for the model used when no depth is uploaded in the app.
* The point clouds are not used. Depth TIFFs are equivalent dense images of the same data.

## Splits

| File | Strategy | train | val | test | dropped |
|---|---|---|---|---|---|
| `experiments/splits/image_wise_seed42.json` | random over scenes, seed 42, 70/15/15 | 620 | 133 | 132 | 0 |
| `experiments/splits/block_wise_seed42.json` | contiguous blocks of 20 scenes, seed 42, gap 2 | 575 | 122 | 116 | 72 |

**Why no true object-wise split.** Object-wise splits need the object ID of each scene. The
original Cornell release provides this in `z.txt`; the local copy does not contain it.
Consecutive scenes often but **not always** show the same object (scene 0100 is a remote;
0103–0105 are a stapler). The block split therefore keeps runs of consecutive scenes together and
drops 2 scenes on each side of a boundary between splits. This reduces, but cannot eliminate,
cases where the same object appears in training and test. **No object-level generalisation
claim is made.**

Regenerate with `python scripts/make_splits.py --seed 42` (deterministic).

## Fixed crop window

Images are cropped to a fixed square before resizing to 224 × 224. The window was chosen once
from the **image-wise training split** (no validation/test annotations): centre = median
positive grasp centre → (304, 275); side = smallest multiple of 16 px with ≥ 99 % of training
positive-rectangle vertices inside → 288 px (99.4 % of vertices, 98.4 % of whole rectangles).
Unlike the GR-ConvNet reference code, the crop is **not centred on the ground-truth grasps of
each image**. That would use test labels at inference time.

## Limitations of the dataset

* 885 scenes of ~240 everyday objects (as reported for Cornell; not verifiable locally). Each
  scene has one object on a white board, seen from above, in one lab.
* Annotations are sparse and incomplete: many valid grasps are not labelled, so a "failure"
  under the rectangle metric can be a plausible grasp.
* Hand-labelled corners are approximately (not exactly) right-angled; the parser accepts up to
  10° deviation.
